## Known Limitations
- **Google OAuth**: Cannot be tested via browser automation (requires third-party redirect). Email/password login covers the same post-auth flow.
- **Coach role testing**: The coach account has no students assigned. To test coach supervision features, a coach_assignment must be created linking the coach to the user test account.
- **Onboarding flow**: All test accounts have `onboarding_completed = true`. To test the onboarding flow itself, create a fresh account or set the flag to `false`.
- **Admin edge functions**: The admin-create-user, admin-list-users, and admin-delete-user functions require a valid admin session token. Tests must log in as admin first.
- **Leaked password protection**: Currently disabled (pre-existing WARN from security linter). Not related to testability.

## Ready for Testing: YES

All three role-based test accounts are created and can log in via `/login` with email/password. The app has stable `data-testid` selectors on all key interactive elements. Routes are healthy with a 404 catch-all. Empty and loading states exist throughout.
